# GovConnect Audit Update — 2026-04-29

> Archive snapshot: this document records the audit state on 2026-04-29 and may be stale. Verify current code, schema, and migrations before using it as implementation guidance.

Status: implementation update for AI gateway/provider runtime hardening.

## Fixed

- Provider `default_headers_json` no longer accepts auth-like headers.
- Runtime gateway headers set `Authorization: Bearer <decrypted-key>` after stored defaults, preventing legacy DB header override.
- Synchronous AI gateway config helpers were removed in favor of async DB-backed runtime config.
- Circuit breaker reset is protected by internal API key middleware.
- Admin provider/model update endpoints are available for DB-backed runtime operations.
- Provider secret decrypt failures mark attempts broken and report provider-health failures.
- Smart-routing probe claims are DB-backed using `FOR UPDATE SKIP LOCKED` plus a 60s `probe_in_flight_until` window.
- `ai_provider_endpoints` is removed; endpoint overrides live on `ai_models.endpoint_path`.
- Wallet ledger `entry_type` is guarded by an idempotent check-constraint migration when legacy data is clean.
- Cross-service response helper and structured logger cleanup were added for selected route paths.

## Verification status

AI service and notification service TypeScript checks pass after these changes. Final runtime verification should still include Prisma generation, test suite execution, migration deploy, and local HTTP smoke checks.
